[role="lead"]
스토리지 플릿은 NetApp Console 로컬 배포에서 함께 관리하는 스토리지 시스템을 그룹화합니다. 폴더를 사용하여 관련 플릿을 그룹화할 수 있습니다. 필요한 범위에서 정책을 적용하고, 액세스 권한을 부여하고, 상태를 모니터링할 수 있습니다.



[[why-fleets-matter]]
== 플리트가 중요한 이유

스토리지 환경이 확장됨에 따라 개별 클러스터를 개별적으로 관리하는 것은 비효율적입니다. 플릿(Fleet)은 관련 스토리지 시스템을 구조화된 방식으로 그룹화하여 하나의 단위로 관리할 수 있도록 해줍니다. 클러스터별로 정책이나 액세스 제어를 구성하는 대신, 플릿 수준에서 한 번만 적용하면 됩니다. 이를 통해 반복적인 관리 작업을 줄이고 플릿 내 모든 클러스터가 동일한 표준에 따라 운영되도록 보장할 수 있습니다.



[[how-folders-and-fleets-organize-your-resources]]
== 폴더와 플릿을 사용하여 리소스를 구성하는 방법

조직의 리소스 계층 구조는 폴더와 플릿으로 구성됩니다. 폴더는 관련 플릿을 그룹화하고, 플릿은 스토리지 시스템을 그룹화합니다.

* *조직*은 계층 구조의 최상위 수준이며 귀사를 나타냅니다.
* *폴더*를 사용하면 관련 플릿을 체계적으로 관리할 수 있습니다. 예를 들어, 각 지역 또는 사업부별로 폴더를 만들고 각 폴더 안에 플릿을 생성할 수 있습니다. 폴더는 다른 폴더나 플릿을 포함할 수 있지만, 스토리지 시스템을 직접 연결할 수는 없습니다. 폴더 수준에서 멤버에게 역할을 할당하면 해당 멤버는 폴더 내의 모든 플릿에 대해 해당 역할을 상속받습니다.
* *플릿*은 관리하는 스토리지 시스템을 그룹화합니다. 스토리지 시스템을 플릿에 연결하고 멤버를 플릿에 할당하여 액세스 권한을 부여합니다.



NOTE: 폴더는 조직 툴이며, 조직 관리자, 폴더 관리자 또는 플릿 관리자 역할 등 IAM 권한이 없는 구성원에게는 표시되지 않습니다. 구성원은 폴더가 아닌 플릿에 액세스합니다.



[[fleet-examples]]
== Fleet 예시

플릿을 구성하는 방법은 운영 모델에 따라 달라집니다. 일반적인 접근 방식은 다음과 같습니다.

* *환경별로* 프로덕션, 개발 및 테스트 워크로드에 대해 별도의 플릿을 생성합니다. 이렇게 하면 프로덕션 스토리지에 더욱 엄격한 성능 및 용량 정책을 적용하는 동시에 하위 환경에서는 유연성을 높일 수 있습니다.
* *사업부별* 특정 부서(재무, 엔지니어링 또는 인사)를 지원하는 클러스터를 전용 플릿으로 그룹화합니다. 그런 다음 다른 플릿을 노출하지 않고 해당 사업부 내 팀원에게 스토리지 관리 책임을 할당할 수 있습니다.
* *위치 또는 데이터 센터별* 클러스터가 여러 사이트에 분산되어 있는 경우, 위치별로 구성하면 사이트 수준의 상태를 모니터링하고, 지역별 계층화 정책을 적용하고, 사이트별 용량 사용량을 추적할 수 있습니다.
* *애플리케이션 계층별* 데이터베이스, 파일 공유 또는 가상 머신 등 특정 유형의 워크로드를 호스팅하는 클러스터를 그룹화하여 전체 클러스터에 해당 워크로드의 성능 프로필에 맞게 조정된 스토리지 클래스를 적용할 수 있습니다.



TIP: 폴더를 사용하여 조직 수준을 한 단계 더 추가하십시오. 예를 들어, 지역별 폴더를 만들고 각 지역 폴더 안에 환경 기반 플릿을 생성할 수 있습니다.



[[how-fleets-connect-to-storage-classes]]
== 플릿과 스토리지 클래스의 연결 방법

스토리지 클래스를 플릿과 연결하면 Console 로컬 배포에서 해당 클래스의 정책을 플릿 내의 모든 스토리지 프로비저닝에 적용합니다. 플릿 내에 프로비저닝된 워크로드는 관리자가 프로비저닝 시 정책 설정을 선택하거나 확인할 필요 없이 스토리지 클래스에 정의된 성능, 용량 및 계층화 규칙을 자동으로 상속합니다. 따라서 플릿은 공통 목적을 수행하는 클러스터 전체에서 일관된 스토리지 동작을 적용하는 기본 방법입니다.



[[how-folders-and-fleets-support-access-control-and-visibility]]
== 폴더와 플릿이 액세스 제어 및 가시성을 지원하는 방법

폴더와 플릿은 사용자 액세스의 경계 역할을 합니다.

* 폴더 수준에서 역할을 할당하면 해당 구성원은 폴더 내의 모든 플릿 및 리소스에 대해 해당 역할을 상속받습니다. 이를 통해 조직 관리자는 폴더를 생성하고 폴더 또는 플릿 관리자 역할을 할당하여 관리 책임을 위임할 수 있습니다. 이렇게 위임받은 관리자는 전체 조직에 대한 액세스 권한 없이도 해당 폴더 내의 모든 플릿을 관리할 수 있습니다.
* *플릿* 수준에서 역할을 할당하면 해당 구성원은 해당 플릿 내의 스토리지 시스템에만 액세스할 수 있습니다.


이를 통해 팀 구성원이나 애플리케이션 소유자에게 스토리지 관리를 위임하면서도 인프라의 관련 없는 부분에 대한 가시성을 부여하지 않을 수 있습니다. Console 로컬 배포는 플릿 수준의 상태 및 성능 모니터링을 제공하므로 단일 화면에서 플릿의 모든 클러스터 상태를 확인하고 문제를 조기에 파악하여 워크로드에 영향을 미치기 전에 조치를 취할 수 있습니다.
