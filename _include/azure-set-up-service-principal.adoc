. Azure에서 Active Directory 애플리케이션을 생성하고 해당 애플리케이션을 역할에 할당할 수 있는 권한이 있는지 확인하십시오.
+
자세한 내용은 다음을 참조하십시오. https://docs.microsoft.com/en-us/azure/active-directory/develop/howto-create-service-principal-portal#required-permissions/["Microsoft Azure 설명서: 필수 권한"^]

. Azure 포털에서 *Microsoft Entra ID* 서비스를 엽니다.
+
image:screenshot_azure_ad.png["Microsoft Azure에서 Active Directory 서비스를 보여줍니다."]

. 메뉴에서 *앱 등록*을 선택합니다.
. *신규 등록*을 선택합니다.
. 애플리케이션에 대한 세부 정보를 지정합니다.
+
** *이름*: 애플리케이션의 이름을 입력합니다.
** *계정 유형*: 계정 유형을 선택하십시오(모든 계정 유형이 NetApp Console에서 사용 가능합니다).
** *Redirect URI*: 이 필드는 비워 두어도 됩니다.


. *등록*을 선택합니다.
+
Active Directory 애플리케이션 및 서비스 주체를 생성했습니다.



. 사용자 지정 역할을 생성합니다:
+
Azure 포털, Azure PowerShell, Azure CLI 또는 REST API를 사용하여 Azure 사용자 지정 역할을 만들 수 있습니다. 다음 단계는 Azure CLI를 사용하여 역할을 만드는 방법을 보여줍니다. 다른 방법을 사용하려면 다음을 참조하십시오. https://learn.microsoft.com/en-us/azure/role-based-access-control/custom-roles#steps-to-create-a-custom-role["Azure 문서"^]

+
.. link:reference-permissions-azure.html["콘솔 에이전트에 대한 사용자 지정 역할 권한"]의 내용을 복사하여 JSON 파일에 저장하십시오.
.. JSON 파일을 수정하여 할당 가능 범위에 Azure 구독 ID를 추가합니다.
+
사용자가 Cloud Volumes ONTAP 시스템을 생성할 각 Azure 구독의 ID를 추가해야 합니다.

+
*예*

+
[source, json]
----
"AssignableScopes": [
"/subscriptions/d333af45-0d07-4154-943d-c25fbzzzzzzz",
"/subscriptions/54b91999-b3e6-4599-908e-416e0zzzzzzz",
"/subscriptions/398e471c-3b42-4ae7-9b59-ce5bbzzzzzzz"
----
.. JSON 파일을 사용하여 Azure에서 사용자 지정 역할을 생성합니다.
+
다음 단계에서는 Azure Cloud Shell에서 Bash를 사용하여 역할을 생성하는 방법을 설명합니다.

+
*** Start https://docs.microsoft.com/en-us/azure/cloud-shell/overview["Azure Cloud Shell"^]를 클릭하고 Bash 환경을 선택합니다.
*** JSON 파일을 업로드합니다.
+
image:screenshot_azure_shell_upload.png["파일을 업로드하는 옵션을 선택할 수 있는 Azure Cloud Shell의 스크린샷입니다."]

*** Azure CLI를 사용하여 사용자 지정 역할을 생성합니다.
+
[source, azurecli]
----
az role definition create --role-definition Connector_Policy.json
----
+
이제 콘솔 에이전트 가상 머신에 할당할 수 있는 Console Operator라는 사용자 지정 역할이 생성되었습니다.





. 애플리케이션을 해당 역할에 할당합니다.
+
.. Azure 포털에서 *구독* 서비스를 엽니다.
.. 구독을 선택합니다.
.. *액세스 제어(IAM) > 추가 > 역할 할당 추가*를 선택합니다.
.. *역할* 탭에서 *Console Operator* 역할을 선택하고 *다음*을 선택합니다.
.. *Members* 탭에서 다음 단계를 완료합니다.
+
*** *사용자, 그룹 또는 서비스 주체*가 선택된 상태를 유지하십시오.
*** *멤버 선택*을 선택합니다.
+
image:screenshot-azure-service-principal-role.png["애플리케이션에 역할을 추가할 때 Azure 포털의 멤버 페이지를 보여주는 스크린샷입니다."]

*** 애플리케이션 이름을 검색합니다.
+
다음은 예입니다.

+
image:screenshot_azure_service_principal_role.png["Azure 포털에서 역할 할당 추가 양식을 보여주는 Azure 포털의 스크린샷입니다."]

*** 애플리케이션을 선택하고 *선택*을 선택합니다.
*** *다음*을 선택하십시오.


.. *검토 + 할당*을 선택합니다.
+
이제 서비스 주체는 콘솔 에이전트를 배포하는 데 필요한 Azure 권한을 갖습니다.

+
여러 Azure 구독에서 Cloud Volumes ONTAP을 배포하려면 각 구독에 서비스 주체를 바인딩해야 합니다. NetApp Console에서 Cloud Volumes ONTAP을 배포할 때 사용할 구독을 선택할 수 있습니다.





. *Microsoft Entra ID* 서비스에서 *앱 등록*을 선택하고 해당 애플리케이션을 선택합니다.
. *API 권한 > 권한 추가*를 선택합니다.
. *Microsoft APIs*에서 *Azure Service Management*를 선택합니다.
+
image:screenshot_azure_service_mgmt_apis.gif["Azure 서비스 관리 API 권한을 보여주는 Azure 포털의 스크린샷."]

. *조직 사용자로 Azure Service Management 액세스*를 선택한 다음 *권한 추가*를 선택합니다.
+
image:screenshot_azure_service_mgmt_apis_add.gif["Azure 서비스 관리 API를 추가하는 Azure 포털의 스크린샷."]



. *Microsoft Entra ID* 서비스에서 *앱 등록*을 선택하고 해당 애플리케이션을 선택합니다.
. *애플리케이션(클라이언트) ID*와 *디렉토리(테넌트) ID*를 복사합니다.
+
image:screenshot_azure_app_ids.gif["Microsoft Entra IDy에서 애플리케이션의 애플리케이션(클라이언트) ID와 디렉터리(테넌트) ID를 보여주는 스크린샷입니다."]

+
콘솔에 Azure 계정을 추가할 때는 애플리케이션(클라이언트) ID와 애플리케이션의 디렉터리(테넌트) ID를 제공해야 합니다. 콘솔은 이러한 ID를 사용하여 프로그래밍 방식으로 로그인합니다.



. *Microsoft Entra ID* 서비스를 엽니다.
. *앱 등록*을 선택하고 해당 애플리케이션을 선택합니다.
. *인증서 및 비밀 > 새 클라이언트 비밀*을 선택합니다.
. 비밀에 대한 설명과 지속 시간을 제공하십시오.
. *추가*를 선택합니다.
. 클라이언트 비밀 값을 복사합니다.
+
image:screenshot_azure_client_secret.gif["Microsoft Entra 서비스 주체에 대한 클라이언트 암호를 보여주는 Azure 포털의 스크린샷입니다."]
