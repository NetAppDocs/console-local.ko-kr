콘솔 에이전트가 Google Cloud의 리소스를 관리하는 데 필요한 권한을 얻으려면 Google Cloud 서비스 계정이 필요합니다. 콘솔 에이전트를 생성할 때 이 서비스 계정을 콘솔 에이전트 VM과 연결해야 합니다.

향후 릴리스에서 새로운 권한이 추가될 경우 사용자 지정 역할을 업데이트하는 것은 사용자의 책임입니다. 새로운 권한이 필요한 경우 릴리스 노트에 명시될 예정입니다.

.단계
. Google Cloud에서 사용자 지정 역할을 생성합니다.
+
.. link:reference-permissions-gcp.html["콘솔 에이전트에 대한 서비스 계정 권한"]의 내용을 포함하는 YAML 파일을 생성합니다.
.. Google Cloud에서 클라우드 셸을 활성화합니다.
.. 필요한 권한이 포함된 YAML 파일을 업로드합니다.
..  `gcloud iam roles create` 명령을 사용하여 사용자 지정 역할을 생성합니다.
+
다음 예제는 프로젝트 수준에서 "connector"라는 이름의 역할을 생성합니다.

+
`gcloud iam roles create connector --project=myproject --file=connector.yaml`

+
https://cloud.google.com/iam/docs/creating-custom-roles#iam-custom-roles-create-gcloud["Google Cloud 문서: 사용자 지정 역할 생성 및 관리"^]



. Google Cloud에서 서비스 계정을 생성하고 해당 서비스 계정에 역할을 할당합니다.
+
.. IAM 및 관리 서비스에서 *서비스 계정 > 서비스 계정 생성*을 선택합니다.
.. 서비스 계정 정보를 입력하고 *생성 및 계속*을 선택합니다.
.. 방금 생성한 역할을 선택합니다.
.. 나머지 단계를 완료하여 역할을 생성합니다.
+
https://cloud.google.com/iam/docs/creating-managing-service-accounts#creating_a_service_account["Google Cloud 문서: 서비스 계정 생성"^]



. Cloud Volumes ONTAP 시스템을 Console 에이전트가 있는 프로젝트와 다른 프로젝트에 배포할 계획이라면 Console 에이전트의 서비스 계정에 해당 프로젝트에 대한 액세스 권한을 부여해야 합니다.
+
예를 들어 콘솔 에이전트가 프로젝트 1에 있고 프로젝트 2에 Cloud Volumes ONTAP 시스템을 생성하려는 경우, 프로젝트 2에서 서비스 계정에 대한 액세스 권한을 부여해야 합니다.

+
.. IAM 및 관리 서비스에서 Cloud Volumes ONTAP 시스템을 생성할 Google Cloud 프로젝트를 선택합니다.
.. *IAM* 페이지에서 *액세스 권한 부여*를 선택하고 필요한 세부 정보를 입력하십시오.
+
*** 콘솔 에이전트 서비스 계정의 이메일 주소를 입력하십시오.
*** 콘솔 에이전트의 사용자 지정 역할을 선택합니다.
*** *저장*을 선택합니다.




+
자세한 내용은 다음을 참조하십시오. https://cloud.google.com/iam/docs/granting-changing-revoking-access#grant-single-role["Google Cloud 문서"^]
